# pr-split — Session Status

Last updated: 2026-05-08

## What we did today

Converted `pr-split` from a standalone Python/Bedrock CLI into a Claude Code plugin. The original tool used `boto3` + AWS Bedrock Claude calls and required a `setup.sh`. The plugin version uses Claude Code's own model and needs zero setup beyond `gh auth login`.

### Built

| Component | Location | Purpose |
|-----------|----------|---------|
| `plan` skill | `skills/plan/SKILL.md` | Read-only analysis: groups changed files into PRs by layer + dependency |
| `execute` skill | `skills/execute/SKILL.md` | Creates branches and opens PRs from the plan |
| `revert` skill | `skills/revert/SKILL.md` | Closes PRs and deletes split branches |
| Pre-push hook | `hooks/check_push_size.sh` + `hooks.json` | Warns when `git push` is about to ship 8+ files |
| Plugin manifest | `.claude-plugin/plugin.json` | Plugin metadata, version 1.1.0 |
| Marketplace manifest | `.claude-plugin/marketplace.json` | Standalone marketplace entry |

Repo: <https://github.com/tanjil-choudhury-cko/pr-split>

### Tested end-to-end

Built a bookstore feature in `RiderProjects/Playground` with 10 files across 4 layers (Models, DTOs, Interfaces, Repository, Service, Endpoints, Program.cs). Successfully ran `/pr-split:plan` + `/pr-split:execute` and created 6 stacked PRs at <https://github.com/tanjil-choudhury-cko/Playground>.

### Issues found during testing → fixed in v1.1.0

| Issue (v1.0.0 behaviour) | Fix in v1.1.0 |
|---|---|
| Skill silently ran `gh repo create` to create a remote it needed | Hard rule: skill MUST NOT run any `gh repo create`/`gh repo edit`. Stops and tells the user to fix. |
| Skill silently ran `git rm -r --cached` to untrack build artefacts | Hard rule: skill MUST NOT modify the working tree, .gitignore, or the origin branch. |
| Skill switched from default `--strategy independent` to `stacked` without saying so | Strategy override discipline: must loudly recommend an alternative, never silently switch. |
| PR descriptions didn't explain coupling between PRs | Every PR body now opens with a coupling notice (independent vs stacked) explaining what reviewers need to know. |
| No way to tell which PRs came from this tool | Every PR body and commit message now includes `🤖 Generated by pr-split` stamp. |
| One blanket confirmation step felt heavy-handed at times | Added `--confirm strict\|normal\|auto`. Strict prompts before each individual PR. |

### Validated v1.1.0 works correctly

Re-ran `/pr-split:plan` after publishing v1.1.0 — the skill correctly detected an orphan `main` branch (left over from earlier testing) and **refused to fix it autonomously**, telling the user what to fix instead. Exactly the right behaviour.

## TODO

### 1. Interactive fix prompts for blockers (next priority)

Right now v1.1.0 stops cold when a blocker is detected and tells the user what to fix. That's safer than v1.0.0's autonomous fixing but loses the convenience.

The fix: keep the safety, add a prompt with the proposed fix written out so the user can approve it explicitly. Pattern:

```
⚠️ Blocker: working tree has uncommitted changes:
   M PlaygroundWebAPI/obj/Debug/net10.0/PlaygroundWebAPI.AssemblyInfo.cs
   M PlaygroundWebAPI/obj/Debug/net10.0/PlaygroundWebAPI.AssemblyInfoInputs.cache

Suggested fix: untrack these build artefacts.
  git rm -r --cached PlaygroundWebAPI/bin PlaygroundWebAPI/obj
  git commit -m "chore: untrack build artefacts"

Want me to apply this fix? (yes/no/show me the exact commands)
```

Apply this same pattern to the other detectable blockers:
- Working tree dirty with build artefacts → offer `git rm -r --cached`
- No `.gitignore` covering build dirs → offer to add one
- No remote → tell the user to add one (do NOT auto-create the repo)
- Orphan `main` / no merge base → offer `git rebase --onto main --root`
- `bin/`/`obj/`/`.idea/`/`node_modules/` files in the diff → offer to untrack

Each prompt must include the exact commands and require explicit "yes" to run. No silent fixes ever.

### 2. Handle test files in the dependency analysis

Currently the plan groups files by static dependency (imports). Tests need special treatment because:

- A test file imports the SUT (system under test) — the dependency analysis would correctly put the test in a later PR, but that means the SUT lands in `main` without its tests.
- CI typically runs the test suite on the merging PR — if PR 2 contains the SUT and PR 5 contains its tests, PR 2 might pass CI without verifying anything substantive.
- Reviewers want to see the test alongside the feature.

Options to consider next session:

| Option | Effect |
|--------|--------|
| **Pair tests with their SUT in the same PR** | Most reviewer-friendly. Increases PR file counts. |
| **Allow tests to "borrow" their SUT into their PR** | Tests PR includes the SUT files at a no-op level. Confusing. |
| **Run the test suite during execute as a pre-flight per-PR** | Catches breakage. Slow. Requires a runner config. |
| **Add a `--test-strategy <pair-with-sut\|separate-pr\|skip>` flag** | Most flexible. Default `pair-with-sut`. |

Likely answer: **pair-with-sut by default**. When the dependency analyser sees `XService.cs` and `XServiceTests.cs` both in the diff, it puts them in the same PR. The `--test-strategy separate-pr` flag is for teams that want a dedicated tests PR after the feature has landed.

### 3. Detect and pair test files

Companion to #2. The skill needs to recognise test files via:
- Filename suffix: `*Tests.cs`, `*.test.ts`, `*.spec.ts`, `*_test.go`, `test_*.py`
- Directory: `tests/`, `__tests__/`, `*.Tests/`
- Imports: file imports a test framework (xUnit, NUnit, Jest, pytest, etc.)

Then when grouping, automatically pair `Foo.cs` with `FooTests.cs` if both are in the diff.

- v1.1.0: stops on every problem, user fixes manually (safe but slow)
